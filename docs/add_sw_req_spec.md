# 추가 요구사항 명세서(반영 필수!)

## 추가 기능 요구사항

1) 주변 상권 정보 조회 OpenAPI 사용하여 정보 가져올 수 있다 하고, 
주변 상권 중 경쟁사가 존재하면 네이버 지도 API 호출 및 웹 크롤링 기능 실행해서 경쟁사 정보를 가져와서 LLM 모델이 거기에서 차별점 정보들을 추출하고 경쟁사 10곳의 리뷰를 요약해서 비교 했을 때, 질문한 소상공인 고객에게 어떤 강점이 있는가? 그런 방식으로 요약해주는 기능 구현 필요.

2) 1)번 사항 결론만 말하자면 경쟁사 리뷰 가져와 가지고 해당 리뷰에 대한 요약 정보 생성 및 비교 필요.

3) 예를들어 인스타그램, 블로그에 포스트 게시물을 올릴 수도 있고 현수막에 짧은 문구를 적고 싶을 수 있다.
하여 그러한 각 문장들을 포맷팅 해가지고 각 플랫폼(인스타그램, 블로그, 현수막 등)에 맞는 방식으로 짧은 문구 적을 수 있는 기능 구현 필요.

4) 각 플랫폼(인스타그램, 블로그, 현수막 등)에 맞는 방식으로 포맷팅 해서 짧은 문구 적을 수 있는 기능 구현 예시
(예) 단순히 이미지 포함된 포스트 게시물 만들자 할 수 있지만 인스타그램에 적절한 방식으로 포스트 게시물 생성해줘.
(예) 블로그 포스트 게시물 쓰고 싶은데 블로그에 적절한 방식으로 포스트 게시물 생성해줘.
(예) 현수막 걸고 싶은데 현수막에 적절한 방식으로 문구 생성해줘.

5) 한 가지 더 예를들어 날씨 정보 같은거나 그러한 것들을 소상공인 사용자가 직접 입력 해줄 수 있겠지만 
AI 모델이 대신 실시간으로 뉴스나 날씨 아니면 트랜드 같은 것을 웹에서 긁어서 가져온다. (웹 크롤링 또는 외부 공개된 API 사용)
하여 해당 데이터들을 가지고 시인성 있는 카피(광고 문구) 생성 및 사용자에게 보여주기
예) 내일 눈이 온다. (추운 겨울에 적절한 카피(광고 문구) 생성), 유행에 맞는 카피(광고 문구) 생성

6) 게시물 생성 노드 추가 구현 - 유료: 광고 이미지 + 문구 
광고 문구를 어디에 올릴지에 따라서 어떤 광고일지 다르다. 
(예) 시골 현수막
(예) 인스타 바이럴 마케팅 - 문구, 이미지 포함된 간단한 소상공인 가게 인스타 계정에 올릴 수 있는 게시물

7) 6)번 기능 구현하기 위해 메인 페이지/회원 로그인 UI, RestAPI 기능 구현 및 DB 테이블(SQLAlchemy, sqlite3) 설계 필요
CASE 1: UI 구현
(예) 로그인 페이지 및 버튼
(예) 메인페이지 사이드바 탭 또는 체크 박스 "게시물 생성"
(예) 메인페이지 "게시물 생성" 탭 또는 체크 박스 클릭 시 "게시물 생성" 팝업화면(OK/Cancel 버튼 포함)

CASE 2: RestAPI 기능 구현
(예) 로그인
(예) "게시물 생성" 팝업화면 OK 클릭 후 사용자가 게시물 생성 요청 건당 유료 결제 처리

CASE 3: DB 테이블(SQLAlchemy, sqlite3) 설계
(예) users - 사용자 정보
(예) payments - 사용자 결제 정보
(예) generations - 광고 문구/게시물 생성
(예) market_cache (신규 — 상권 조회 결과 캐시)

8) 상권 분석 또는 업종 분석 노드 추가 구현
예를 들어 소상공인 업종 중 카페라고 하면 다른 카페에서 유행되고 있는 메뉴 추천(또는 추가적으로 개발할 수 있는 메뉴 추천)
왜냐하면 다른 가게에서 다 팔 수 있는 메뉴로는 광고 효과 없음.
하여 다른 가게와 다른 차별점 미리 추천 필요. (문구 반영)
아래 예와 같은 방식으로 기능 구현 및 서비스 제공 시 사용자에게 편의성 제공 가능.
(예) 식품 - 두쫀쿠, 의류, 유행 제품, 상권 정보 OpenAPI 사용 및 거리 계산 하여 반경 몇 미터 내(거리 내) 유일한 제품 판매하는 카페, 주말에 더운 곳에 갔다 왔는데 반경 몇 미터 내 최대한 가깝고 시원한 카페 등

9) AI 모델 답변 검증 평가 지표 활용 및 대규모 평가 필요
(예) RAGAS-Score, LLM Judge, Hit Rate @5, MRR (Mean Reciprocal Rank), Context Recall, Context Precision 등.

10) 시연 시나리오 "강남역 근처 카페인데 여름 신메뉴 홍보 문구 만들어줘" 대로 만드는 광고 문구의 경우 차별점 없다고 생각함.
하여 이에 따른 대안으로 LLM 모델 쓰다 보면 사용자가 질문했을 때 또 다른 안을 제시해 준다. 
(예) LLM 모델 답변 마지막에 1번 또는 2번 안 선택 시 이에 따른 추가 답변 드리겠습니다

11) 팀 프로젝트에서 직접 구현할 때 어느 정도의 성능이 나올지는 모르지만 사용자 질문에 부족한 정보들을 LLM 모델이 대신 구분 후 사용자에게 LLM 모델이 꼬리 질문 형식 답변 처리 및 사용자가 해당 꼬리 질문 입력 시 LLM 모델이 그에 따른 광고 이미지, 문구 생성 기능 구현 필요
(예) 가격대가 얼마인지?, 주요 고객이 어느 연령대인지? LLM 모델이 꼬리 질문 후 사용자가 그에 따른 답변 입력하면
LLM 모델이 해당 꼬리질문 답변 반영 하여 광고 이미지, 문구 생성함.

12) 트렌드 또는 생성중 문구 미리 100개 정도 저장해 놓고 라이브시연 진행 시 소상공인 AI 챗봇이 광고 문구, 이미지 생성 하는 대기 시간 동안 사용자가 지루하지 않게 미리 100개 정도 저장해둔 문구를 랜덤으로 5초 마다 띄워주는 느낌의 대기 화면 출력
이유: 대기 시간 오래 걸려도 사용자가 유하게 받아들일 수 있다고 생각함.  
사용자가 원하는 좋은 결과물(광고 문구, 이미지 등)이 나오는게 중요함.

13) 컨설턴트 챗봇 기능 구현: 웹 메인 페이지 좌측 사이드 바 "컨설턴트 챗봇"버튼 클릭 챗봇 화면 출력 되면서 컨설팅 업무 진행

- 주의사항: 기본 챗봇, 컨설턴트 챗봇 둘 다 메인 챗봇 프로그램이고 이들을 포함한 소상공인들의 통합 플랫폼 개발 진행 필요함.
- (예) 기본 챗봇: 광고 문구+이미지 생성만 실행, 컨설턴트 챗봇: 메뉴 제안, 컨설팅 등(소상공인 주변 상권 Open API, 네이버 데이터랩 API 등 활용)

- 소상공인 사용자들의 필요에 따라 두 가지 종류 챗봇 프로그램 이용 가능.
- 소상공인들의 통합 플랫폼 개발하는게 타팀과 다른 차별점 있다고 생각함.

17) 로컬 테스트/평가 진행(운영 배포 대상 제외) -> 코드잇 제공 OpenAI API 호출 -> HTTP 통신 요청 텀(시간)이 짧아서 또는 한 번에 여러 번 HTTP 통신 요청할 경우 HTTP Status Code 429 오류 발생 -> 다른 OpenAI API 호출 로직 구현(예: 김재헌/조희원 개인 크레딧)
HTTP Status Code 429 오류 발생 원인: HTTP 통신 요청 텀(시간)이 짧을 때 또는 한 번에 여러 번 HTTP 통신 요청할 때 발생함.

18) 운영 배포 이후 -> 소상공인 사용자 직접 AI 서비스 이용 -> 사용자가 광고 문구/이미지 생성 또는 컨설팅 요청 -> 코드잇 제공 OpenAI API 호출 -> HTTP 통신 요청 텀(시간)이 짧아서 또는 한 번에 여러 번 HTTP 통신 요청할 경우 HTTP Status Code 429 오류 발생하는 건이 최소화 하도록 
OpenAI API 호출 기능 실행 시 HTTP 통신 요청 텀(시간)을 늘리는 방식 또는 사이에 Step 추가하거나 또는 여러 번 HTTP 통신 요청하지 못하도록 하여 서비스 부하를 줄이는 기능 구현 및 설계 필요.
