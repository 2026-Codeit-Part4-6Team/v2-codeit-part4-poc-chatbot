2) [MVP 추가] v6 신규 기능 요구사항 (add_sw_req_spec.md 반영)
ID: FR-19 / 기능: 보안1: 입력 검증 노드 / 입력: 사용자 질의 / 출력: 프롬프트 인젝션·탈옥 차단, 불법 광고 요청 거부 / 근거: add 16
해당 기능 노드 구현 시 아래 예시처럼 법률 관련 OPEN API 사용해서 구현할 경우
(예) 국가법령정보 공동활용 OPEN API - https://open.law.go.kr/LSO/openApi/guideList.
OPEN API 호출 후 데이터 받아 온 뒤에 데이터 정제(가공, 파싱)하는 프로세스가 너무 많다고 생각함.
또한 OPEN API 호출 후 응답 데이터를 받고 해당 데이터 정제(가공, 파싱)하는 프로세스 처리 후 LLM, 이미지 생성 모델이 해당 데이터와 사용자 광고 문구, 이미지 생성 요청 내용을 가지고 추론하는데 소요되는 시간이 오래 걸릴것 같음.
하여 아래 예시처럼 키워드 기반으로 해당 기능 노드를 구현하는게 쉽게 구현할 수 있다고 생각함.
(예) 마약과 같은 불법 키워드가 들어간 경우 챗봇이 한 번더 사용자에게 다시 질문하는 형식으로 기능 구현
(예) 불법적인 품목을 파는 것들은 키워드에 대한 것만 규제하면 된다.
(예) 우리 가게가 최고다라는 광고 문구, 이미지 등을 소상공인 사용자가 요청할 때도 챗봇이 그런 표현은 부적절하며, 광고 문구 및 이미지 생성 불가 안내.
